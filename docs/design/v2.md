# Design v2: premium by default, unique by design

*Lead decision, 2026-10-20. Owner's verdict from in game: every UI now shares one identity, but the HUD,
speedometer and map still don't feel premium, in look or in what they do. v2 fixes both.*

## The goal

nuikit should be **the fastest way for a server to own a premium, unique UI**: one premium identity out of the
box, and a token system that turns it into the server's own identity by changing a handful of values. A brand
colour isn't enough.

Today's tokens are shadcn colours plus game semantics. Colour is the only thing a server can change, so every
nuikit server looks like the same product in a different colour. That's the gap. What makes a UI premium and
recognisable is mostly **not colour**. It's type, shape, surface, density, motion and how data is drawn
(gauges, meters, rows). v2 makes those tokens too.

## 1. Token architecture: three tiers

Additive to tokens v1 (`docs/tokens.md`): nothing is renamed or removed, so every existing theme and UI keeps
working. This is tokens v1.1.

```
identity  (~20 values a server sets)      →  type, shape, surface, density, motion, brand, HUD style
semantic  (v1 + a few new)                 →  background, primary, success, hud, vital-*, surface tiers…
component (derived, each one overridable)  →  --nk-panel-*, --nk-row-*, --nk-gauge-*, --nk-chip-*, --nk-key-*
```

Components read **only** component tokens. Component tokens default to formulas over identity + semantic. A
server changes identity values for a new look. A designer overrides one component token for a detail. Nobody
edits component code.

### Identity tokens

| Group | Token | What it changes | Default (Graphite) |
|---|---|---|---|
| Brand | `--brand`, `--brand-foreground` | The server's signature colour, separate from `--primary` (the action). Used for the active indicator, gauge needles, focus and logos. Derived from `--primary` when that's chromatic, else from `--chart-1`. | derived |
| Type | `--font-sans` (v1), `--font-display`, `--font-numeric`, `--font-mono` (v1) | Body, headings and big moments, every number on a gauge/money/timer (tabular) | Inter / Inter Tight / Geist Mono |
| | `--nk-type-ratio` | Step between type sizes (1.125 calm … 1.333 dramatic) | `1.2` |
| | `--nk-weight-body` / `-strong` / `-display` | Weight personality | `400 / 600 / 700` |
| | `--nk-tracking-display`, `--nk-label-case`, `--nk-tracking-label` | Display letter-spacing; labels in `uppercase` or `none` | `-0.02em`, `none`, `0` |
| Shape | `--radius` (v1), `--nk-border-width`, `--nk-cut` | Corner radius; hairline weight; chamfered corners (0 = off), drawn with `clip-path` | `0.625rem`, `1px`, `0` |
| Surface | `--nk-surface-opacity` | Panel opacity over the game (floor 0.92 for text panels) | `0.96` |
| | `--nk-surface-tint` | How much `--brand` tints neutral surfaces (0–0.12) | `0.02` |
| | `--nk-surface-gradient` | Top-to-bottom light falloff on panels (0 = flat) | `0.04` |
| | `--nk-surface-edge` | Inner top highlight, the "machined edge" (alpha) | `0.06` |
| | `--nk-elevation` | `none` / `soft` / `deep` shadow recipe | `soft` |
| | `--nk-glow` | Brand glow on active parts and HUD fills (alpha, 0 = off) | `0` |
| Density | `--nk-density` | Multiplies the spacing scale (0.85 compact … 1.15 roomy) | `1` |
| Motion | `--nk-motion` (v1), `--nk-ease`, `--nk-duration` | Personality: snappy or smooth | `cubic-bezier(.2,.8,.2,1)`, `160ms` |
| HUD | `--nk-hud-opacity`, `--nk-hud-text-shadow`, `--nk-gauge-style`, `--nk-gauge-track`, `--nk-gauge-ticks` | Backplate strength; legibility over the sky; `arc` / `bar` / `digital`; track thickness; tick marks on/off | `0.55`, `soft`, `arc`, `0.375rem`, `1` |

The compiler derives everything a theme leaves out, as v1 does for semantics, so a plain TweakCN paste still
works. It also warns when values break the floors (surface opacity < 0.92, contrast vs `#fff` for HUD text).

### Component tokens (first set)

`panel` (bg, border, radius, padding, shadow, edge, cut), `row` (height, radius, active bg, **active indicator:
`bar` / `fill` / `outline`**), `key` (the `Kbd` look), `chip`, `meter` (track, fill, glow, segments), `gauge`
(arc sweep, needle, redline, ticks, numeral font), `heading` (display size, case). The full list and the
formulas live in `docs/tokens.md` once step 1 lands.

## 2. Identities: four premium starting points

A server picks one and tunes it, or uses it as a reference for its own. Each is a `theme.css`, one file. Each
must stand on its own as a finished product. Original work; nothing copied from any server.

| Identity | Character | Key values |
|---|---|---|
| **Graphite** (default) | Precise, calm, neutral; reads as a well-made product | Inter, flat surfaces with a machined edge, `bar` row indicator, arc gauges |
| **Signal** | Bold and street; big condensed display type, cut corners | condensed display, `--nk-cut: .5rem`, uppercase labels, high-contrast brand, `fill` rows |
| **Velvet** | Soft and warm, luxury | rounded, gradient surfaces, deep elevation, smooth motion, serif or soft display |
| **Vector** | Tactical instrument | mono numerals, thin hairlines, `outline` rows, ticks everywhere, digital gauges, slight glow |

Proof that the system works: **the same screens, rendered in all four identities, side by side** on the site and
in game, switched live with `nuikit theme reload`.

## 3. Flagship: HUD, vehicle and map, premium in what they do

The owner's bar is functionality *and* look. The rebuilt `nuikit_hud` ships:

- **Placement:** anchored to GTA's safe zone and the real minimap rect, read from Lua and recomputed on
  resolution or aspect change (16:9, 21:9, 32:9).
- **Vitals:** health, armor, hunger, thirst and stress through the bridge. Shown on change or below a threshold,
  then faded back. Icon + colour + value, never colour alone.
- **Vehicle cluster:**
  - speed (km/h or mph pref) and a gauge with ticks and a redline;
  - RPM, gear (R/N/1–n) and a shift light;
  - fuel through an adapter (ox_fuel, LegacyFuel, cdn-fuel, then the native);
  - engine and body damage warnings;
  - seatbelt and cruise through adapter hooks; lights, indicators and handbrake;
  - aircraft and boat variants: altitude, heading and airspeed.
- **Map and location:**
  - a themed frame around GTA's radar;
  - street, cross street and zone, plus a heading compass;
  - an optional postal (adapter);
  - waypoint distance.
- **Cost:** event-driven, with `nk.stream` only for gliding values. Budget ≤ 0.02 ms idle and ≤ 0.08 ms driving
  in resmon, measured and published in the PR.
- **Config:** every element can be turned off, and gauge style comes from the identity. Player-movable layout
  is a later step.

## 4. The baseline is utilitarian (owner direction, Oct 20)

The owner shared NoPixel V reference shots. What we take is the **principles**, never the look: no italic
condensed type, no slanted slabs, no layouts copied 1:1. Their quality is minimal, neat and compact, and every
element earns its place. That is nuikit's starting point: Graphite becomes the utilitarian baseline. The other
identities show how far the tokens stretch from it.

**Principles**
1. **Integrate, don't add.**
   - The compass lives on the minimap ring: cardinal marks rotate around it and the heading reads above it.
   - The waypoint distance is a tag on the ring.
   - Location sits as two lines under the map.
   - One cluster per job: the map, the vehicle, the player.
2. **Compact by default.** Small footprint, tight grouping, generous empty screen. Information sits where the eye
   already is (map corner, vehicle corner); nothing floats alone.
3. **Show on need.**
   - Vitals are compact labelled pills with a thin level line, shown on change or threshold.
   - Status effects are small icon dots, shown only when active.
   - Telltales are a narrow icon column beside the gauge, lit only when on.
4. **One-glance numerals.**
   - The speed is big, with dim leading zeros (`0`40).
   - The gear sits in the arc's centre.
   - Ammo reads as `12 / 48`.
   - Numbers use the numeric font; labels are small caps-style captions.
5. **Uniform slabs for transient feedback:**
   - item add/remove: icon tile + name + delta;
   - prompts: key chip + verb;
   - progress: label + thin line + cancel key;
   - incapacitated: a full-width band at the bottom.
   Same anatomy everywhere, so new scripts look native.
6. **Flexible, not locked.** Layout is a preset over the same parts (`compact` default, `classic` = today's
   bottom-left map). Every part is a component a developer can place, restyle through tokens, or replace. The
   tokens encode *qualities* (density, shape, surface, type), never one server's look.

**Minimap paint layer: what's possible on FiveM (spike before committing)**

NoPixel V runs on its own framework, so the way it repaints the map may not be available to FiveM. Three routes
exist on FiveM:
- (a) **Shape and frame:** GTA's radar clipped to a circle (`SetMinimapClipType`) and positioned by the
  `minimap` component natives, with nuikit's ring + compass drawn around it. Proven pattern; the radar's colours
  stay GTA's.
- (b) **Repaint through streamed textures:** a resource streams replacement minimap textures (the `.ytd` map
  tiles, the way "dark/atlas map" packs do). We could generate tiles tinted from the theme's tokens at build time.
  Needs: which textures, file size, load cost, and whether tint-from-tokens is practical.
- (c) **Own map:** hide the radar and draw the map in NUI from pre-rendered tiles + player position. Fully
  themeable, but the most cost (a moving image at 30–60 fps) and blips must be re-sourced.

The default is (a). (b) is the premium option if the spike shows it's cheap. (c) is only for a server that wants
it.

## 5. From research to systems (lead synthesis, Oct 20)

Four research docs in `docs/design/research/`:
- `premium-qualities.md`
- `motion.md`
- `system-architecture.md`
- `game-ui-patterns.md`

Their common conclusion: premium is *nothing reads as cheap*. That means:
- instant response;
- purposeful, interruptible motion;
- every state designed;
- rhythm;
- restraint in colour and ornament;
- type that carries hierarchy;
- zero cost when idle.

nuikit adopts it as systems, not one-off polish, in this order.

**A. Motion system** (lead, after identity lands)
- Motion tokens derived from `--nk-duration`: press, hover, base, exit (0.7×), move, modal, screen, stagger, and 5 easings. Springs are pre-sampled into Web Animations keyframes (no CSS springs before Chromium 113+).
- A small dependency-free helper, `nuikit-core/motion`, for springs, retargeting, FLIP and timed runs. No Motion or react-spring in the kit.
- Kit base hardening: no text selection or image drag, themed scrollbars, and `nk-pop`, `nk-press`, `nk-stagger`.
- **Instant keyboard and controller state:** no transition on focus or selection moves. The selection indicator slides once per move, with a key-repeat rule.
- Reduced motion in two levels: `--nk-motion: 0` means off; the player pref means reduced (fades ≤ 100 ms are kept).
- Fixes: `meter` animates `scaleX`, not `width`; `skill-check` becomes one WAAPI rotation; `progress-ring` becomes one compositor animation.
- Budget: zero frames when idle; ≤ 1.5 ms per frame while animating.

**B. System hardening** (lead)
1. `cn()` that knows `nk-*`, via `extendTailwindMerge` generated from `kit.css`, with tests for the two class pairs that broke.
2. A CI step that runs `pnpm sync` and fails on drift.
3. A component contract (`docs/design/contract.md`), the merge checklist: tokens only, the full state set, motion, controller focus, identities plus Daylight.
4. Registry `meta`: since, status, replacement, plus a deprecation policy.
5. Visual regression baselines across identities in the Chromium 103 binary, with axe checks.

**C. Input and focus service** (0.7 runtime, `docs/architecture.md` step 3)
- One focus model for mouse, keyboard and pad: hover and focus are one state.
- Spatial navigation and focus memory, as our own small module.
- The pad is read in Lua and forwarded by the controls service.
- Key hints show the player's real binding (`GetControlInstructionalButton`) and switch glyphs with the active device. Glyphs are original text labels, never console trademarks.

**D. Notification and HUD-visibility services** (0.7 intents)
- Notifications in four lanes (feed, toast, banner, moment), with priority, queueing, dedupe "×N", merged money and item deltas, per-resource rate limits and a history.
- HUD visibility (hidden, peek, full) driven by change, threshold or player request. The HUD v2 show-on-change logic becomes this service.

**E. Later, after spikes**
- UI sound: one Web Audio context with preloaded buffers; game frontend sounds as the fallback.
- Scene-aware tokens: Lua sends a scene class (day, dusk, night, snow, interior) only when it changes.
- The device layer for phones: frame, peek state, app shell, app modules on the host loader.
- Menu shell (tabs, breadcrumb, detail pane, action bar) and settings from a prefs schema.

**Spikes for the owner's test session.** These decide C–E:
- pad input while NUI has focus;
- CEF audio without a user gesture;
- an idle off-screen page producing zero frames;
- sampled springs vs cubic-bezier at high refresh rates;
- `clip-path` animation smoothness;
- the minimap tile repaint (`bench/minimap/`).

## Steps (each ships on its own)

1. **Identity layer.** Spike first on a real client: fonts served from the `nuikit` resource to other
   resources' pages (`nui://nuikit/fonts/…`), `clip-path` cut corners, and gradient + edge surfaces at 60 fps on
   Chromium 103. Then the compiler, `index.css.tpl` / `kit.css` component tokens, the four identities, the
   schema/DTCG files and docs. *Ships:* every nuikit UI and override can be restyled into a distinct identity
   today.
2. **Flagship HUD, vehicle and map** on component tokens (above), tested in game in all four identities.
3. **Components and screens read component tokens** (Components and Screens lanes): menu-row, meter,
   speedometer, panel, notice, then ox_lib, ox_inventory, pause and death.
4. **Figma:** each identity as a variable mode in the design system file; reference screens per identity.

## Unproven (what would change this)

- **Fonts across resources.** If one resource's page can't load fonts from `nui://nuikit/`, `pnpm sync`
  bundles the identity fonts into every UI instead. That costs size, not design.
- **Surface effects.** If gradients, edges or glow cost frames over the game, identities keep them as tokens
  but the defaults go flat, and the compiler warns.
- **Text sizes.** The research recommends 16 px body and 18 px+ HUD (`docs/design/research.md` §3). That gets
  confirmed in game during step 2.
- **Fuel, seatbelt and postal** have no standard across frameworks. Adapters cover the common ones; others fall
  back to the native or are hidden.
